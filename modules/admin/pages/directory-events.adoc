= Справочник {ne}

Справочник {ne} отвечает за настройку событий, которые требуют уведомлений. Когда возникает определенное событие, оно требует отправки уведомлений по нему. Событием является, например, завершение задания на согласование. События используются в карточке настроек уведомления для настройки того, какие уведомления рассылать, кому, куда и т.д.

.Справочник представлен в виде таблицы со следующими полями:
Идентификатор::
Идентификатор карточки, связанной с событием.

Название::
Название события, по которому его можно легко идентифицировать.

Описание::
Назвёрнутое описание события.

Тип карточки::
Идентификатор типа карточки.

Вид карточки::
Идентификатор вида карточки.

Состояние карточки::
Идентификатор состояния карточки.

[#new-event]
== Создание нового события

.Чтобы добавить новое событие уведомлений:
.	Откройте справочник событий и добавьте новую строку в таблицу кнопкой image:buttons/plus.png[Плюс].
.	В поле _Название_ укажите понятное название для события.
.	В поле _Описание_ укажите необязательную дополнительную информацию.
.	В поле _Тип карточки_ укажите идентификатор типа карточки, для которого создаётся событие. Событие в справочнике не может использоваться для разных типов карточек.
.	В поле _Вид карточки_ (опционально) укажите идентификатор вида карточки, для которого создаётся событие или пустой идентификатор. Если указан пустой идентификатор, событие совместимо с карточками всех видов.
.	В поле _Состояние карточки_ (опционально) укажите идентификатор состояния, в котором применимо данное событие. Если указан пустой идентификатор, событие совместимо с карточками во всех доступных состояниях.
.	Сохраните событие нажатием кнопки *Сохранить*.
. Чтобы удалить событие, нажмите на кнопку image:buttons/urn.png[Урна].

[#examples]
== Примеры

Пример 1::
Поскольку процесс {bo} обращается к Cервису уведомлений при переходе задания в состояние `На приёмке`, можно создать уникальное событие _Задание перешло на приёмку_:
+
. В поле _Название_ укажите: "Задание перешло на приёмку".
. В поле _Тип карточки_ укажите ID типа _Задание_.
. В поле _Вид карточки_ укажите ID вида заданияfootnote:[ID вида необходим для дополнительного фильтра по состоянию], для которого применимо событие.
. В поле _Состояние карточки_ укажите ID состояния `На приёмке` требуемого вида.

Пример 2::
Дополнительно можно создать событие, которое будет совместимо со всеми карточками выбранного типа независимо от состояния (или вида и состояния).
+
.Для этого:
. В поле _Тип карточки_ укажите ID типа.
. В поле _Вид_ укажите ID вида.
. В поле _Состояние_ укажите пустой идентификатор (или укажите пустой идентификатор в полях _Вид_ и _Состояние_).
. При обращении сервис уведомлений выбирает из справочника наиболее подходящее событие, соответственно данное событие будет выбрано только при отсутствии других зарегистрированных событий для текущего вида и состояния карточки.

Пример 3::
Дополнительно можно создать "пустое" событие, которое будет использоваться для исключения рассылки в конкретном случае. Например, чтобы рассылка не выполнялась при возврате задания на доработку:
+
. Зарегистрируйте в справочнике событие из "Примера 2" и прияжите его к карточке рассылки.
. Зарегистрируйте новое событие _Отказ в приёмке_:
+
... В поле _Вид карточки_ укажите вид задания.
... В поле _Состояние карточки_ укажите ID состояния _На доработке_ выбранного вида.
+
. Не привязывайте новое событие к карточке рассылки.
В этом случае при переходе задания указанного вида на доработку из справочника будет выбрано событие _Отказ в приёмке_, а при переводе на приёмку -- общее событие из "Примера 2".
