= Создание расписания

Расписание является карточкой, связанной с карточкой рассылки. Карточка расписания не может существовать без карточки рассылки. Для доступа к настройке расписания нужно в карточке настроек рассылки установить флаг `*Периодическая рассылка*`.

.Флаг "Периодическая рассылка"
image::sending-schedule.png[Флаг "Периодическая рассылка"]

Затем следует указать способ выборки карточек, способ выбора дней для выполнения рассылки, способ выбора времени суток в назначенный день и общий срок активности данного расписания.

Дополнительно можно изменить порядок формирования уведомлений, установив флаг `*Альтернативная рассылка сообщений*`. Альтернативный порядок формирования уведомлений позволяет нормировать процесс создания уведомлений за счёт добавления события "Запрос на построение уведомления по шаблону" для Службы регистрации событий уведомлений, тем самым уменьшив нагрузку на процесс сервиса, но увеличив общее время обработки. Рекомендуется использовать альтернативную рассылку сообщений только в случае, когда обработка периодической рассылки создаёт большую нагрузку на систему.

== Основные настройки

Основные настройки расписания задают способ определения карточек, для которых происходит запланированное событие. Для этого назначаются два компонента: источник данных и постобработка данных.

.Основные настройки расписания
image::sending-general.png[Основные настройки]

Источник данных создаёт неупорядоченный набор объектов для создания уведомлений. Это может быть поисковый запрос или другой компонент для выборки. Если выбранный компонент использует строковый параметр при работе, значение параметра нужно указать в строковом поле ниже. Например, для поиска карточек необходимо указать ID поискового запроса или полный текст XML.

Собственные компоненты источника данных перед использованием в карточках необходимо добавить в Справочник {nss} на вкладке _Периодические: Источники данных_.

.Вкладка "Периодические: Источники данных" в Справочнике {nss}
image::setting-dir-sources.png[Периодические: Источники данных]

Постобработка данных нужна для фильтрации и группировки выбранных источником объектов. Если компонент постобработки не выбран, все выбранные объекты будут обработаны как единая группа (будет сформировано одно уведомление по всем объектам). Компонент постобработки может менять изначальную коллекцию объектов по своей логике и разделять их на группы, объединённые по некоторому признаку. Для каждой такой группы уведомления будут сформированы независимо друг от друга. Если выбранный компонент использует строковый параметр при работе, значение параметра нужно указать в строковом поле ниже.

Собственные компоненты постобработки данных перед использованием в карточках необходимо добавить в Справочник {nss} на вкладке _Периодические: Постобработка_.

.Вкладка "Периодические: Постобработка" в Справочнике {nss}
image::settings-dir-post.png[Периодические: Постобработка]

== Расписание

Блок _Расписание_ содержит элементы управления для задания дней, в которые должно исполняться событие. Видимость отдельных элементов управления контролируется выбранными значениями в других элементах.

На первом уровне выбирается основная единица вычисления даты: день, неделя или месяц.

.Расписание по дням
image::sending-schedule-days.png[Расписание по дням]

Тип периода _По дням_ позволяет назначить расписание ежедневно или через равное количество дней. Выходные и рабочие дни при этом не разделяются.

.Расписание по неделям
image::sending-schedule-weeks.png[Расписание по неделям]

Тип периода _По неделям_ позволяет назначить расписание еженедельно или через равное количество недель, а также выбрать дни исполнения в эту неделю.

.Расписание по месяцам
image::sending-schedule-months.png[Расписание по месяцам]

Тип периода _По месяцам_ позволяет назначить расписание ежемесячно или через равное количество месяцев. Однако, при данном типе периода разрешается выбрать только `1` день в месяце: или указать число месяца, или выбрать день одной из недель (например, первый понедельник месяца).

== Периодичность в день

Блок _Периодичность в день_ позволяет настроить однократное или многократное срабатывание расписания в выбранный день.

.Блок "Периодичность в день"
image::sending-schedule-periodic.png[Блок "Периодичность в день"]

Для типа _Однократно_ следует указать время суток срабатывания расписания.

Для типа _Повтор через Х минут/часов_ следует указать период в минутах/часах и время суток начала и завершения повтора рассылки. Например, если указать `каждые 2 часа с 2:30 до 8:00`, рассылка будет выполняться в 2:30, 4:30, 6:30.

== Продолжительность

В блоке _Продолжительность_ можно назначить дату начала и завершения действия текущего расписания. Например, если рассылку следует начать не сегодня, или нужно автоматически прекратить в какой-то день.

.Блоке "Продолжительность"
image::sending-schedule-duration.png[Блоке "Продолжительность"]

Как и в случае рассылки по событию, возможно построение нескольких уведомлений по разным шаблонам. В поле _Ссылки_ можно указать одну или несколько карточек настроек уведомлений. Любая карточка настроек может использоваться в нескольких карточках рассылки.
